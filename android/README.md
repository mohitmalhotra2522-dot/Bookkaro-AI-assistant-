# BookKaro Android (P40) — debug shell + native IRCTC WebView

Kotlin, Android-Studio-compatible (AGP 8.5.2, Kotlin 1.9.24, Gradle 8.7, JDK 17). minSdk 26, targetSdk 34.
Debug APK only — not for the Play Store.

## Build
```
cd android
echo "sdk.dir=/path/to/Android/sdk" > local.properties     # Android Studio writes this for you
./gradlew testDebugUnitTest assembleDebug                   # → app/build/outputs/apk/debug/app-debug.apk
# other BookKaro server (e.g. staging):  ./gradlew assembleDebug -Pbookkaro.url=https://example.onrender.com/
```

## Architecture
- `MainActivity`: a WebView on the HTTPS BookKaro web app (JS, DOM storage, cookies on; no file / universal access).
  It opens the bridge `BookKaroAndroid` (WebViewCompat.addWebMessageListener, BookKaro origin + main frame only).
  The page sends only `BK_PING` and `BK_IRCTC_HANDOFF {handoffId, bridgeToken, reviewVersion}`, the same three
  P39.3 binding values the desktop extension receives.
- `core/HandoffController`: fetches the signed P39.3 snapshot from the backend, then guards it.
  - Guard checks: schema, handoffId, reviewVersion, expiry, backend status, and HMAC-SHA256 with the bridge token.
    `core/HandoffGuard` is a Kotlin port of `extension/irctc-handoff-guard.js` and is tested against shared vectors.
  - It re-fetches and re-guards on every IRCTC step.
  - The handoff is kept in memory only, so process death means no replay. Terminal or consumed handoffs are refused.
- `IrctcActivity`: a WebView on `https://www.irctc.co.in/nget/train-search`.
  - Script injection: ONE predefined document-start script, IRCTC origin only. It is
    `assets/irctc-android-adapter.js` wrapping the UNMODIFIED `extension/irctc-handoff-guard.js`, `irctc-core.js`
    and `irctc-content.js`, copied into the APK at build time by `syncIrctcScripts`.
  - Bridge: `BookKaroIrctc`, IRCTC origin + main frame only.
  - Token handling: the bridge token never reaches the IRCTC page.
- Mock IRCTC (localhost:3000 / 5173) is allowed in the debug build only.

## Tests
- `./gradlew testDebugUnitTest` runs JUnit on the guard, URL policy, bridge protocol, controller and navigation/script.
- Vectors: `app/src/test/resources/p40-handoff-vectors.json` is generated by `scripts/p40-android-vectors.ts` from
  the real backend handoff code and the extension JS guard. It is test data only, with a mock session.
- JS side: `tests/unit/p40-android-bridge.test.ts` (vitest + happy-dom + MockIRCTC).

## P40.1 (v0.40.1)
- IRCTC links tapped on the BookKaro page open the app's own IRCTC WebView (never the external browser).
- Spoken replies: `assets/bookkaro-tts-shim.js` (BookKaro origin only) + `web/NativeTts.kt` route the existing web
  voice flow's `speechSynthesis` to the phone's system TTS (Android WebView has no speech engine of its own).
